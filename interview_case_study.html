Executive Summary

How modern technical writers use Python not to write application features, but to build automated pipelines that govern, validate, and deploy technical documentation at scale.

🎙️ How to pitch this in an interview:
"Engineering teams deploy code hundreds of times a week using automated CI/CD pipelines. If technical writers rely on manual copy-editing in Word documents, documentation becomes the bottleneck. Step 1 in Pipeline

Taxonomy & Frontmatter Validation

Enforcing structured metadata at the header of every markdown document for search filtering, version tracking, and categorization.

📋 Why Frontmatter Matters:
Enterprise docs engines (Docusaurus, MkDocs, Nextra) require YAML frontmatter. If an engineer publishes an API page without a title, category, or firmware_version, search indexing breaks and users cannot filter docs by hardware revision. 
---
title: "ODrive Axis State Machine & Calibration Architecture"
description: "Operating states, calibration sequences, and closed-loop transitions."
category: "Core Architecture"
firmware_version: "v0.5.6"
status: "production"
last_reviewed: "2026-08-14"
tags: ["axis", "state-machine", "calibration", "closed-loop"]
---
💡 Interview Talking Point:
"I wrote FrontmatterValidator in Python using PyYAML to enforce schema rules. It checks for mandatory keys, verifies ISO 8601 dates (YYYY-MM-DD), and ensures categories match our formal Information Architecture taxonomy."
Step 2 in Pipeline

Editorial Governance & Inclusive Language

Automating editorial style guides to eliminate legacy terms, subjective fluff, and anti-patterns.

Flagged Anti-Pattern Suggested Replacement Editorial Rationale
master / slave controller / target or primary / secondary Inclusive terminology; aligns with modern IEEE & Linux standards.
blacklist / whitelist blocklist / allowlist Inclusive, direct, and unambiguous technical terminology.
click here Descriptive text (e.g. "View the CAN Protocol Guide") SEO and accessibility (screen readers need destination context).
simply / obviously / easy to use Direct imperative action (e.g. "Run the command") Subjective filler undermines authority and frustrates struggling users.
H1 jumping to H3 H1 → H2 → H3 Heading hierarchy skips break screen reader navigation and table of contents trees.
🛠️ Auto-Remediation Feature (--fix):
"To accelerate developer adoption, I added an automated --fix flag to the CLI. Writers and engineers can run python doc_health_check.py --fix to instantly remediate standard terminology across dozens of documents in seconds."
Step 3 in Pipeline

Link & Anchor Integrity Checker

Preventing 404 dead-ends across local markdown anchors, relative file paths, and external HTTP URLs.

1. Heading Anchor Slugs
Converts document headings to GitHub slug format (e.g. ## Current Limits → #current-limits) and verifies intra-doc anchor links point to real headings.
2. Inter-File Relative Links
Verifies that references like [Motor Specs](./motor_configuration.md) resolve to existing physical files on disk relative to the current doc.
3. Remote HTTP Verification
Uses requests with HTTP HEAD/GET caching and timeouts to detect broken remote documentation links before publishing.
Step 4 in Pipeline

AI Tone & Voice Sanitizer (Gemini Integration)

Using Large Language Models to enforce imperative technical voice and eliminate passive phrasing.

Draft Prose (Passive / Conversational) AI Sanitized Output (Direct Imperative)
"The calibration should be started by the user before closed loop is entered." "Calibrate the motor before entering closed-loop control."
"It can be observed that when overvoltage happens, the drive trips." "Overvoltage conditions trigger a safety shutdown."
"Please note that the baud rate must be saved and rebooted." "Save the configuration and reboot the controller to apply baud rate changes."
🤖 AI-Ready Technical Writing Philosophy:
"I built a two-tier AI review engine: when online, it calls the Gemini API with an editorial system prompt for deep tone critiques; when offline or in fast CI runs, it uses deterministic regex heuristics to catch passive voice patterns without external API latency."
Step 5 in Pipeline

H2/H3 Semantic Chunking for AI & RAG

Bridging technical writing structure and AI retrieval: slicing documents at logical conceptual task boundaries.

🎯 The Core Interview Insight:
"Most software engineers chunk text naively by character count (e.g. every 500 characters). This cuts code blocks and sentences in half, causing RAG retrieval failures. Because I understand Information Architecture, I built an H2/H3 heading-based semantic chunker that preserves self-contained task units, document titles, and anchor URLs." 
{
  "chunk_id": "axis_states_chunk_03",
  "doc_title": "ODrive Axis State Machine & Calibration Architecture",
  "section": "Step 1: Run Full Motor and Encoder Calibration",

  "estimated_tokens": 142,
  "text": "### Step 1: Run Full Motor and Encoder Calibration\n\nExecute the calibration sequence using odrivetool..."
}

ODrive Forum Scraping & Error Mining

Mining developer support communities to turn unstructured troubleshooting threads into structured API documentation.

Community Fix: Shield encoder wires, increase current_lim_margin to 8.0A.

Community Fix: Connect 50W 2Ω resistor, set enable_brake_resistor = True.

Step 7 in Pipeline

Continuous Integration & GitHub Actions Gating

Automating quality gating on every Git push and pull request. 

name: "Docs-as-Code Quality Gate"
on: [push, pull_request]

jobs:
  doc-health-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.11" }
      - run: pip install -r requirements.txt
      - name: "Run ContentOps Linter (Strict Gating)"
        run: python doc_health_check.py --path docs/valid --strict --offline
      - name: "Build RAG Semantic Chunk Index"
        run: python doc_health_check.py --chunk --path docs/valid
🛡️ Release Management Impact:
"If an engineer opens a pull request with broken markdown links, missing frontmatter, or non-inclusive terminology, our GitHub Action fails and blocks the PR merge. Quality enforcement is shifted left into the development workflow."
